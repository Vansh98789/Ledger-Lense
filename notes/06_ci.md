# 06. CI/CD Regression Guard (Step 6)

## 1. Overview
Step 6 establishes an automated Quality Gate in GitHub Actions to ensure future code modifications (prompts, retrieval algorithms, chunking strategies) never degrade production RAG quality.

---

## 2. Gatekeeper Policy
Every pull request modifying AI components must pass the following thresholds:

| Metric | Minimum Target | Action if Failed |
|---|---|---|
| **Retrieval Hit@5** | ≥ 85.0% | ❌ Block Pull Request Merge |
| **Answer Correctness** | ≥ 85.0% | ❌ Block Pull Request Merge |
| **Answer Faithfulness** | ≥ 85.0% | ❌ Block Pull Request Merge |

---

## 3. Workflow Architecture

```text
PR Created / Code Pushed to 'backend/app/**' or 'evals/**'
                       │
                       ▼
          GitHub Actions (.github/workflows/eval.yml)
                       │
                       ▼
          1. Setup Python 3.13 + Tesseract OCR
                       │
                       ▼
          2. Run Evals: `python evals/step_5_results/run_evals.py`
                       │
                       ▼
          3. Check Quality: `python evals/step_6_ci_guard/regression_check.py`
                       │
             ┌─────────┴─────────┐
             ▼                   ▼
       Any Metric < 85%?   All Metrics ≥ 85%?
             │                   │
           ❌ FAIL             ✅ PASS
      Merge BLOCKED        Merge ALLOWED
```
